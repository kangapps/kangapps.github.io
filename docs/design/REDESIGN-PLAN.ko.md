# JK Apps 디자인 업데이트 계획

대상: 메인 목록, 6개 앱 상세, 공통 내비게이션과 지원·개인정보 페이지의 탐색 일관성. Minmi는 목록의 외부 링크만 유지하며 상세 리디자인에서 제외한다. 현재 서비스 파일은 수정하지 않고 계획과 비교 시안만 제공한다.

## 현재 구현에서 확인한 문제

정적 HTML과 페이지별 인라인 CSS로 구성되어 있고 별도 빌드 시스템은 없다. README 외 별도 디자인 가이드가 발견되지 않았다. 아래는 소스 확인 결과이며 실제 브라우저 렌더링·키보드·스크린리더 검증은 미실시다.

|우선순위|근거|개선|
|---|---|---|
|P0|boxingtimer/index.html:133, bakeweigh/index.html:133의 스토어 ID가 id0000000000|실제 배포 URL과 출시 상태를 확인하기 전 다운로드 CTA 노출 금지|
|P1|index.html의 .apps와 7개 app-card가 단일 평면 목록|게임·유틸리티 섹션과 전체/카테고리 필터 제공|
|P1|상세 공통 구조가 아이콘 → 기능 카드 → 하단 CTA|앱 가치, 플랫폼·출시 상태, 핵심 CTA를 첫 화면에 배치|
|P1|각 파일의 독립 style 블록|공통 CSS 토큰·카드·버튼·푸터를 공유해 변경 비용 축소|
|P2|상세 페이지에 실제 사용 화면 자산 없음|실제 캡처 확보 후 스크린샷 갤러리 추가. 가짜 화면·리뷰·평점 사용 금지|

## 정보 구조

- 게임: Pipixel, Number Match: Pair Puzzle, Bloceraze, ColorSort: Candy Tubes.
- 유틸리티: Boxing Timer(운동), BakeWeigh(요리), Minmi(AI·macOS, 외부 사이트 표시).
- 7개 규모에서는 검색·정렬보다 카테고리 탐색을 우선한다. 전체 화면에서도 두 카테고리를 제목으로 구분한다.
- 플랫폼과 출시 상태는 서로 다른 정보로 표현한다. Coming soon은 플랫폼 배지를 대체하지 않는다.
- 현재 저장소 문구는 배포 사실로 간주하지 않는다. Number Match·Bloceraze는 출시 예정 문구가 있으며 다른 앱도 스토어 연결과 상태를 별도로 확인한다.

## 상세 페이지 공통 설계

1. 브랜드 내비게이션과 전체 앱으로 돌아가기.
2. 아이콘, 앱 이름, 한 문장 가치 제안, 플랫폼·출시 상태, 검증된 스토어 CTA.
3. 실제 앱 캡처 3~5장. 캡처가 없으면 해당 섹션을 생략한다.
4. 주요 사용 상황 3개와 이를 뒷받침하는 기능. 기존 기능 사실은 유지하고 표현을 정돈한다.
5. 지원·개인정보 링크와 목록 복귀. 출시 예정 앱은 다운로드 버튼 대신 출시 상태를 명확히 표시한다.

게임은 플레이 규칙·진행·휴식 경험을, Boxing Timer는 라운드 설정·훈련 중 가독성을, BakeWeigh는 재료별 환산·레시피 배율을 우선 설명한다. Minmi 상세는 만들지 않는다.

## 세 방향과 인터랙티브 비교

`interactive-concepts.html`은 Arcade를 기본 화면으로 열고 Studio · Light를 전환 옵션으로 제공하며, 카테고리 필터와 6개 앱 상세 진입·복귀를 지원한다. 실제 앱 아이콘과 기존 기능 문구를 사용한다. Minmi만 실제 외부 링크다. 상세 화면은 기능 정보를 비교하는 시안이다. 실제 앱 페이지로 연결되는 버튼은 두지 않고, 지원·개인정보 링크와 확인된 스토어 링크만 제공한다.

|방향|시각·구조|장점과 비용|
|---|---|---|
|Studio — 추천|따뜻한 중립색, 비대칭 히어로, 4열 앱 카드와 원본 앱 아이콘|플레이와 생활 도구가 함께 있는 컬렉션을 빠르게 훑기 좋음. 아이콘이 화면의 유일한 강한 색 포인트|
|Editorial|종이색, 세리프 헤드라인, 2열 정렬 목록과 가는 구분선|독립 제작자의 차분한 인상을 강조. 아이콘으로 앱별 성격을 구분|
|Arcade|짙은 중립 배경, 3열 카드, 원본 아이콘의 채도를 강조|게임의 활기를 살림. 유틸리티도 같은 위계로 노출해 컬렉션 균형 유지|

적용안: Arcade를 기본 다크 화면으로 설정하고, Studio(1안)를 Light 테마 전환 옵션으로 둔다. 앱 아이콘 색을 포인트로 쓰고 본문·내비게이션은 테마별 중립색으로 정돈한다. Editorial은 방향 비교 설명에만 남긴다. 시안 언어는 현재 사이트와 맞춰 영어로 구성했다.

## Unslop 적용 기록

적용 스킬: [unslop](https://github.com/heydamir/unslop), Damir Sokolovsky, CC BY 4.0. 시안 하단에 저작자와 라이선스를 표시했다.

기존 시안 감사 결과:
- `SMALL APPS. EVERYDAY DELIGHT.`는 대문자와 넓은 자간으로 주의를 분산했다. 문장형 소문자 레이블로 교체했다.
- `Make room for something good.`는 앱의 실제 용도를 설명하지 못했다. `Games to pick up. Tools to keep close.`로 게임과 도구의 컬렉션임을 드러냈다.
- 앱 카드와 상세가 같은 기능명 나열에 그쳤다. 앱별 원문 설명을 카드와 상세에 배치하고, 상세에는 확인된 기능 설명을 연결했다.
- 임시 출시 문구와 스토어 링크가 섞일 수 있었다. 확인된 출시 예정 상태만 표시하고 `0000000000` 임시 ID 링크를 숨겼다.

방향 다섯 줄:
- Product: JK의 게임과 생활 도구를 발견하고 세부 정보를 확인하는 앱 컬렉션
- Character: 목적이 분명하고, 밝고, 친근함
- World: 퍼즐과 주방 도구가 한 작업대 위에 놓인 작은 제작자의 선반
- Moments: 실제 앱 아이콘을 모아 보여주는 히어로와 각 앱의 구체적인 기능 문구
- Signature: 원본 아이콘을 색의 포인트로 쓰고 카테고리별로 선반처럼 묶음

적용 순서: 간격과 카드 밀도 정리 → 중립색과 한 가지 강조색 → 아이콘 외 장식 제거 → 앱에 맞는 구체적 문구 → 무게 400~600의 타이포 위계 → 비대칭 히어로와 카테고리 구획 → 간결한 경계·반경 → 실제 아이콘과 기능을 보여주는 시각 구성 → 짧은 색상 전환만 남김.

## UI 시스템과 UX 기준

- 콘텐츠 최대 폭 1240px, 모바일 좌우 20px, 8px 간격 체계. 목록은 모바일 1열 → 중간 2열 → 데스크톱 4열.
- 본문 16px/1.6, 제목 32~64px 반응형, 설명 줄 길이 약 60자. 긴 앱 이름은 줄바꿈하고 생략하지 않는다.
- 배경·표면·본문·보조문구·경계·강조·포커스에 의미 기반 CSS 변수를 둔다. 실제 렌더링 대비를 측정하여 본문 4.5:1, 큰 글자·의미 있는 UI 3:1 충족.
- 링크는 이동, 버튼은 필터·상태 전환에 사용. 포커스 표시, 선택 상태 텍스트/aria-pressed, 44px 권장 터치 영역, 필터 결과 개수 안내.
- 모션은 최소화하고 prefers-reduced-motion을 따른다. 외부 링크에는 외부 이동을 표시한다.
- 필터 결과 없음(확장 시), 아이콘 로딩 실패, JS 비활성 상태에서도 탐색 가능한 기본 목록을 설계한다. 현재 시안은 JS 기반 비교용이다.

## 실행 순서와 완료 기준

1. 콘텐츠 정리: 7개 앱 분류, 6개 상세 문구·출시 상태·스토어 URL 표 작성. 미확인 링크는 공개 CTA에서 제외.
2. 시안 결정: Studio / Editorial / Arcade에서 목록 밀도, 브랜드 인상, 상세 정보 순서 선택. 실제 캡처 확보.
3. 공통 기반: 정적 HTML 유지, 공통 CSS·최소 JS 분리. 기존 URL과 지원·개인정보 경로 보존.
4. 메인 구현: 카테고리 섹션, 필터, 상태 배지, Minmi 외부 표시. JS 없이도 전체 목록 표시.
5. 상세 6개 적용: 공통 템플릿과 앱별 강조색·콘텐츠 적용. 지원·개인정보는 본문을 보존하고 공통 탐색·타이포 적용.
6. 검수: 320/375/768/1440px 및 200% 확대에서 잘림 없음, 전체 키보드 흐름, 필터와 뒤로가기, 접근성 이름·상태, 대비, 모션 감소, 이미지 대체·실패, 모든 내부/스토어 링크 확인. 스크린리더 수동 검증 별도 기록.

완료는 목록 → 카테고리 → 상세 → 검증된 다운로드 또는 출시 상태 → 지원/목록 복귀 흐름 전체가 동작하는 시점으로 정의한다. 성능은 변경 전후 같은 조건으로 측정하고 이미지 크기·레이아웃 이동·불필요한 스크립트를 점검한다.

## 검증 범위

저장소의 7개 진입 HTML과 아이콘·링크·기능 문구를 확인해 시안을 구성했다. 인터랙티브 시안은 데스크톱 브라우저에서 렌더링했고, 카테고리 필터·상세 진입/복귀·디자인 전환을 확인했다. 390px 화면에서 가로 넘침이 없는 것도 확인했다. 실제 서비스 페이지, 실제 스토어 배포 상태, 320px·200% 확대·보조기기 동작은 확인하지 않았다. 본 문서는 구현 계획이며 접근성 적합 판정이 아니다.
